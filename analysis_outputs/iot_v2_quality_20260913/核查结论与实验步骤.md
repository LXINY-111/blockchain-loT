| 账户热点 | 各段最大单账户涉及的交易份额：训练 16.8935%、验证 19.826%、测试 17.274%；最高单账户有向邻接计数分别 5,997、5,733、5,229 | 真实交易图本身不均衡，会形成不可忽略的负载约束；不能仅凭 PPO 分片集中归咎于跨片权重 |

| 特征数值范围 | 各段实际首次放置场景特征均无非有限值；训练段距离最大 0.786695、通信强度最大 0.865889、通信代价系数最大 0.683425，三者均未全部顶格 | 没有发现通信/距离特征因归一化全部失效；关系数量到上限的训练账户占 0.4659% |
| 原始时长 | 94,332 笔（31.444%）时长为 0；原值中位数 144，最大 15,845,942,856；当前只保留原值 | 单位仍未核实。本轮延续现有归一化强度及零时长回退，不能解释成真实字节/秒。物理速率研究前必须解决该问题 |
| 零链路质量 | 正向零质量 35,390 笔（11.7967%）；同位置按质量 1 处理的场景有 5,926 笔（1.9753%） | 零质量来自原始有向模板，不是缺失值；同位置质量 1 是构造假设，不是原始实测。当前代价项不等同于真实网络断连仿真 |
| 模板复用和分布 | 使用 64,698 条不同模板，235,302 次分配复用旧模板；两个最小画像池仅 54 和 150 条；测试段 89.262% 的模板分配使用此前出现过的模板 | 冻结同一场景库是本轮比较的既定条件，不构成独立新增测量样本；将来扩数据规模不会自动增加场景多样性 |
| 画像并非均衡交易量 | 每种画像账户数为 1,939—2,090，较接近；但训练交易的发送方画像中最高一类占 29.3875% | 账户映射近似均衡，不等于交易流量均衡；热点账户的稳定画像会放大某些通信类型 |

这里的“有向邻接计数”将账户作为发送方的不同接收方数与作为接收方的不同发送方数相加，双向同一对端可能计两次。它不是拓扑中的无向唯一邻居数。特征分布则按系统的不同对端集合定义计算。

协议分布相对训练段的总变差距离为验证 0.017945、测试 0.02283；发送方画像分布对应值为 0.044945 和 0.071785。该距离为各类别比例绝对差之和的一半，范围 0—1；这里只描述变化，不用任意阈值宣布分布完全相同。

## 当前适合跑什么

第一轮只回答：在同一套新数据、同一窗口和原系统参数下，PPO 是否能学到有效放置，并与哈希、启发式、仅候选评分作可解释比较。先保留原奖励权重和状态结构，不边跑边改数据、去重、替换时长单位或调权重。

训练 20 万笔、验证 5 万笔、测试 5 万笔；种子 7；16 分片；每批 1,000 笔；15 轮；候选数 7；容量保护关闭；全局奖励权重为 0.55/0.30/0.10/0.05。原有局部奖励机制保持。模型由验证段的既有评分规则选择，测试段不参与调参。确定性 PPO 是主比较；这轮先不另外启动采样策略、消融或多种子实验。

| 数据段 | 从 0 开始的区间 | 实际账户数 | 用途 |
|---|---|---:|---|
| 训练 | [0, 200000) | 43,573 | 学习参数 |
| 验证 | [200000, 250000) | 23,100 | 按已有规则选模型 |
| 测试 | [250000, 300000) | 23,024 | 冻结模型后与三个基线比较 |

完成单种子离线对照后，再做 1 万笔链上验收；验收完成后，正式链上策略比较统一使用同一完整测试窗口和相同注入率。下方命令中的链上步骤只启动 PPO 验收，不代表完成了所有链上基线对照。

## 操作 4：同一个测试窗口跑四种策略

```powershell
foreach ($policy in @('hash', 'heuristic', 'candidate_only', 'ppo')) {
  $evaluation = @(
    '--policy', $policy, '--start_tx', '250000', '--max_txs', '50000',
    '--model', $v2Model,
    '--log_jsonl', (Join-Path $v2Run ('eval_' + $policy + '.jsonl'))
  )
  python -B .\spring_lite\eval_offline.py @common @evaluation
  if ($LASTEXITCODE -ne 0) { throw "Evaluation failed: $policy" }
}

$comparison = foreach ($policy in @('hash', 'heuristic', 'candidate_only', 'ppo')) {
  $record = Get-Content -LiteralPath (Join-Path $v2Run ('eval_' + $policy + '.jsonl')) -Tail 1 -Encoding UTF8 | ConvertFrom-Json
  [pscustomobject]@{
    policy=$policy
    txs=$record.loaded_txs
    cross_ratio=$record.summary.cross_ratio
    reward=$record.summary.reward_mean
    balance=$record.summary.r_wlb_mean
    active_shards=$record.summary.active_shards_mean
    max_load_share=$record.summary.max_load_share_mean
    communication_cost=$record.summary.communication_cost_mean
    action_distribution=($record.summary.action_dist -join ',')
  }
}
$comparison | Export-Csv -LiteralPath (Join-Path $v2Run 'comparison.csv') -NoTypeInformation -Encoding UTF8
$comparison | Format-Table policy,txs,cross_ratio,reward,balance,active_shards,max_load_share -AutoSize
Write-Output $v2Run
```

哈希和随机在代码中不使用候选过滤，不能为了让参数表看起来相同而给哈希额外套候选选择。本轮运行的启发式、仅候选和 PPO 保留候选规则。主 PPO 不加 `--sample`，使用确定性动作。不要把训练期间的采样结果与测试期间的确定性结果当作同一种评估。

先保留这组结果，再分析跨片率、均衡项、活跃分片数、最大负载份额、通信代价和动作分布。不能只因跨片率更低就判断整体更好，也不要求事先保证 PPO 胜出。后续调参看验证段，不根据测试段反复挑模型。
