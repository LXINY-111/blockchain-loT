优先级说明：P1 表示应优先修复，会破坏正确性或使无效结果被接受；P2 表示测试可靠性或当前未使用辅助路径的问题。每项都区分实际复现和静态证据。

1. **[P1] 收到停止信号后，主执行路径可在数据库关闭前结束。**

   [messageHandle.go:103](E:/project_iot/block-emulator-main-iot/consensus_shard/pbft_all/messageHandle.go:103) 收到 stopCh 即从 Propose 返回，而 [build.go:68](E:/project_iot/block-emulator-main-iot/build/build.go:68) 调用后没有等待退出完成。另一 goroutine 中的 [pbft.go:307](E:/project_iot/block-emulator-main-iot/consensus_shard/pbft_all/pbft.go:307) 此时可能还在等待已接收的 handler。main 返回会终止整个进程，新增 WaitGroup 因而不能保证提交处理及两类数据库关闭完成。复现中阻塞一个已接收 handler，触发 beginStop 后 Propose 立即返回，而 handler 尚未完成。应区分“请求停止”和“停止已完成”，主函数必须等待后者；对无法完成的 handler 再设计有界取消机制。

2. **[P1] PBFT 用指针去重投票，同一节点可被重复计票。**

   [toolFuncs.go:22](E:/project_iot/block-emulator-main-iot/consensus_shard/pbft_all/toolFuncs.go:22) 将 *shard.Node 作为 prepare/commit 计数键。JSON 每次反序列化都会产生新的对象，因此相同 NodeID 的重复消息具有不同键。实际复现将同一发送者消息解码 3 次，得到 3 票；四节点配置的阈值正好是 3。应按稳定节点身份计票，并验证分片成员身份及消息所属轮次。此问题涉及重复消息或重放场景，不表示当前无重复消息的每轮共识都已失效。

3. **[P1] 从节点保留已确认交易，换主后可再次打包并执行。**

   注入消息发送到所有副本，但仅提议节点通过 PackTxs 移走交易。其余节点在 [pbftInside_module.go:60](E:/project_iot/block-emulator-main-iot/consensus_shard/pbft_all/pbftInside_module.go:60) 提交后，没有从本地交易池移除区块中的交易；[blockchain.go:229](E:/project_iot/block-emulator-main-iot/chain/blockchain.go:229) 也没有清理。复现中两个节点接收同一交易，从节点接受第一个区块后生成下一块，旧 TxHash 再次出现在区块中。状态更新又没有已执行交易去重，可能重复改变余额；即使不换主，从节点队列也持续保留这些交易。应在所有节点提交成功后清理对应交易，并在执行层防止重放。

4. **[P1] 区块校验接受错误 StateRoot，落库时也不核对重算结果。**

   [blockchain.go:300](E:/project_iot/block-emulator-main-iot/chain/blockchain.go:300) 仅检查父哈希和交易树根；复现把空块 StateRoot 改成任意 32 字节，仍得到有效结果。[blockchain.go:241](E:/project_iot/block-emulator-main-iot/chain/blockchain.go:241) 在找不到声明的根时虽重算状态，却只打印结果，然后仍将传入块写为 CurrentBlock。应校验状态根、区块高度与头哈希，失败时返回错误，且 PBFT 不能继续推进成功状态。这个复现证明错误状态根被接受，尚未断言历史区块已发生此问题。

5. **[P1] 落后节点补块起点偏移一块，且恢复失败仍推进序号。**

   静态证据：[messageHandle.go:285](E:/project_iot/block-emulator-main-iot/consensus_shard/pbft_all/messageHandle.go:285) 从 sequenceID+1 请求旧块，但 sequenceID 初始化为当前链高+1，本来就是下一块。例：链高 5，sequenceID=6，追赶到 8 时实际请求 7–8，遗漏 6；AddBlock 会拒绝高度不连续的区块。[messageHandle.go:377](E:/project_iot/block-emulator-main-iot/consensus_shard/pbft_all/messageHandle.go:377) 又忽略恢复处理结果，随后把序号设为 9，可能形成“协议序号已前进，链高仍停留”的状态。应从下一缺失高度请求，并仅在完整连续安装成功后推进序号。未对正在运行的集群注入丢块故障。

6. **[P1] 最终状态测试没有把账户重复或少量余额错误作为失败。**

   静态证据：[resultcheck_test.go:78](E:/project_iot/block-emulator-main-iot/query/resultcheck_test.go:78) 只要任一分片找到余额正确的副本，就将账户记为正确；跨片重复账户数量只打印。[resultcheck_test.go:94](E:/project_iot/block-emulator-main-iot/query/resultcheck_test.go:94) 对所有共识模式都容许少于 BrokerNum 个错误。当前 Relay 配置的 BrokerNum=10，因此 1–9 个余额错误也可以正常退出。测试仅读取各分片 N0，不能证明四个副本最终状态一致。应针对当前单归属 Relay/IoT 方案断言账户唯一性、零余额错误，并单独核验副本区块与状态根一致性；Broker 的允许差异必须根据真实 broker 身份限定。

7. **[P1] finalizer 把跳过的状态测试记为 passed。**

   [resultcheck_test.go:46](E:/project_iot/block-emulator-main-iot/query/resultcheck_test.go:46) 在缺数据库时执行 Skip；[finalize_exp8_block_run.py:106](E:/project_iot/block-emulator-main-iot/spring_lite/finalize_exp8_block_run.py:106) 只检查 go test 退出码，随后固定写入 passed。SKIP 的退出码同样为 0。隔离复现提供 SKIP 输出与零退出码，finalizer 仍写出 state_check=passed；复现使用模拟子进程结果，没有访问实际实验数据库。应读取结构化测试结果，要求 TestFinalResult 确实执行并通过，同时验证分析所需的完整性字段后才生成完成标记。

8. **[P1] protocol_ok 未检查延迟数据覆盖率，也未拒绝交易超额计数。**

   [analyze_result9_multiobjective.py:150](E:/project_iot/block-emulator-main-iot/spring_lite/analyze_result9_multiobjective.py:150) 的 valid_latency_ratio 是有效行数除以现有行数，不是对预期交易总数的覆盖率；[同文件:209](E:/project_iot/block-emulator-main-iot/spring_lite/analyze_result9_multiobjective.py:209) 对完成比例只设下限。两项隔离复现均错误通过：预期 200 万笔、仅 1 条有效延迟记录；预期 200 万笔、计数却为 200.1 万笔。应分别报告行内有效率和完整覆盖率，并核对唯一交易数、交易窗口和完整完成数量；缺数据或重复计数应拒绝通过。

9. **[P1] protocol_ok=false 的运行仍进入正式均值和对照表。**

   [analyze_result9_multiobjective.py:254](E:/project_iot/block-emulator-main-iot/spring_lite/analyze_result9_multiobjective.py:254) 未过滤失败运行，all_protocol_ok 只是附加字段；正式表格的选择和展示也没有据此排除或隔离。[同文件:306](E:/project_iot/block-emulator-main-iot/spring_lite/analyze_result9_multiobjective.py:306) 会照常输出这些聚合结果。复现把一条有效跨片率 0.8 的运行，与未完成运行的 0.0 汇总，正式统计均值变成 0.4。应保留失败运行供诊断，但正式对比只能使用完整通过且配置可比的运行。此为合成复现，并非宣称现有归档的均值已经受到同样污染。

10. **[P1] chain 测试直接递归删除实验配置目录。**

    [blockchain_test.go:56](E:/project_iot/block-emulator-main-iot/chain/blockchain_test.go:56) 与 [merkleproof_test.go:82](E:/project_iot/block-emulator-main-iot/chain/merkleproof_test.go:82) 调用 os.RemoveAll(params.ExpDataRootDir)，没有使用测试专属临时目录。当前源代码默认值是仓库外 Result9 的 PENDING_TIMESTAMP 路径；这些测试不会自动读取 paramsConfig.json，所以不能简单等同于“当前运行目录必然被删”。但一旦源代码默认目录中存在数据，普通 go test 就会删除它。此次通过 overlay 的 TestMain 重定向到新建审计目录后才运行，未删除实际实验目录。正式修复应为测试使用 t.TempDir，并恢复全局参数。

11. **[P2] 默认 Go 测试依赖当前可变实验配置，正式测试窗口必然触发失败。**

    [global_config_test.go:81](E:/project_iot/block-emulator-main-iot/params/global_config_test.go:81) 固定要求 TotalDataSize=444019 和 DatasetStartTx=2500000。当前配置是 test2M 窗口，因此 TestParamsConfigJSONTargetsResult9ValidationRun 实际失败：2000000 != 444019。这不是测试集窗口本身非法，而是模板测试与运行实例共用一个可变文件。应将验证集模板、测试集模板和当前运行配置分开，分别验证协议合法性；不要为使测试变绿而覆盖正在运行的配置。

12. **[P2] DeleteElementsInList 切片上界错误。**

    [toolFuncs.go:194](E:/project_iot/block-emulator-main-iot/consensus_shard/pbft_all/toolFuncs.go:194) 返回 list[:-removedCnt]。删除 0 个元素时返回空列表，删除至少 1 个时上界为负数并 panic；“删除 0 个应保留原交易”已实际复现失败。当前检索只找到定义，没有发现生产调用，因此它不是第 3 项重复交易问题的现行原因。修复上界后再将经过验证的清理逻辑接入提交路径，不能直接启用现有辅助函数。
