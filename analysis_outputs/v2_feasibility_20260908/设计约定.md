**v2 可行性计算前的设计约定（2026-09-08）**

本文冻结本轮统计定义，计算完成后在《v2实施规划与可行性结论》中给出推荐方案。这里只创建独立分析工具，不修改业务源码、当前运行配置、旧数据和实验结果。

**研究问题**：有明确业务含义、在决策时只能使用已到达信息的共享状态放置，是否比强贪心基线进一步减少实际跨片执行开销，并在相同输入和资源条件下改善容量或尾延迟？PPO收益是待验证假设。

**候选业务**：设备或监测代理根据观测到的双向网络flow，产生一条服务使用记账事件。actor是记录所属设备/报告主体，不自动等于网络请求发起者。共享状态是服务级使用计数或额度记账对象；这是研究者构造的应用模型，不是原始数据中已发生的链上交易。最小实现可用每事件1个记账单位的账户转移表示，payload保留为统计元数据，不当作实际交易字节。

**本轮比较的定义**：所有定义保留相同的4,944,019条现有有效记录，未纳入共享映射的记录退回原设备私有状态，避免删掉困难流量获得虚假提升。

| 代号 | 定义 | 地位 |
|---|---|---|
| D0 | 从现有state key中机械删除device字段，保留原peer/service/protocol | PDF直接改法的反事实诊断，不认定业务正确 |
| D1 | 现有IP方向明确且远端为单播IP时：remote IP + remote port + application protocol；其他记录保留原私有state | 方向归一候选，仍依赖旧全量primary IP推断 |
| D2 | 在D1基础上要求协议和远端端口匹配冻结的常见服务表；其他记录保留原私有state | 保守服务共享候选，不把未识别协议偷偷删掉 |

端口表在分析脚本中固定，不从效果中学习：dns53、http80/8080/8000、tls443/8443、ntp123、ssdp1900、mdns5353、dhcp67/68、stun3478/5349、classic-stun3478、sip5060/5061、xmpp5222/5269/5223、rtsp554、rtmp1935、ipp631、snmp161/162、syslog514/6514、smb139/445、nbns137、llmnr5355、isakmp500/4500。单播检查使组播/广播服务记录回退。该表只是保守筛选规则，不证明应用语义或完整覆盖。

**时间与信息**：本轮首次批次统计使用已有全局tx_index顺序，每1000条为一个已收齐的批次，仅衡量此规则下可见的访问者。它不是已证明的逐笔在线到达协议。真实部署须在flow可用时间到达后收集批次，计入等待延迟；原始flowDuration单位及time字段的起止含义未确认前，不宣称该统计无任何未来信息。

**热点检验**：actor分片固定为现有地址后8位十六进制模16。每次访问actor分片至少执行1个stage；同片访问总计1个stage，跨片访问两端各1个stage。故任何state放置的最大分片stage数至少为max(最忙actor分片访问量，最热不可拆分state访问量)。分别报告全量、历史train/validation/test开发窗口与连续100,000条窗口，不把比例降低当作最忙分片绝对工作量下降。

**无训练比较**：Hash、FirstActor、FirstBatchMajority为可按所述可见性实现的规则；FutureMajority只作未来完整访问序列下跨片数下界，不是在线基线，也不是容量最优解。

**通信检验**：先复算现有Python与Go通信权重，检查同一批次固定权重和两端实现差异。再用Intel公开有向链路成功概率构造一个明确标注为假设模型的16分片网关场景：静态几何最远点选16个网关，每条正概率有向边代价1/p，最短路径给出期望逐跳传输次数代理。该计算只证明动作能否改变定义明确的代理成本，不是实测网络字节、延迟或能耗。距离用于选址/描述，不能在1/p之外任意重复加权。

**止损原则**：不会预设“90%单访问者”等普适阈值，不按PPO表现挑选state定义；不因状态数减少就人为切时间桶，不因热点高就无成本拆分语义上不可拆分的对象。原始源数据只读，全部本轮统计视为开发诊断，不再称未触碰最终测试。

**基于原始身份审查的定义补充（D3计算之前记录）**：原始4,944,041条flow的srcMac/dstMac全部为空；全量最常见IP并不能作为在线身份规则。增加D3：文件所属设备是报告actor；从当前记录两端中选择唯一满足“协议+冻结服务端口表+单播IP”的服务端点，作为跨设备共享服务记账对象；有零个或两个不同候选时，回退到“报告设备+无序IP端点对+应用协议”的私有端点对记账对象。私有回退不使用临时端口，不声称它是会话级状态。该业务记录端点对累计流量，而不是每个网络会话独立余额。D3 key不读取全量primary IP或未来访问者。服务业务在此定义下有意合并同一应用服务的不同传输协议，原始ipProto仍须作为正式v2元数据保留。增加D3的原因是因果身份缺口，不是任何PPO表现。本轮不运行PPO。
